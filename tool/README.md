# tool/

Manually-run maintenance scripts. Nothing here is wired into CI or the build.

## `generate_brand_assets.py`

Regenerates every derived brand asset from `assets/icon/cairn_foreground.png`
— the stones on a transparent canvas — which is the single approved source of
truth for the Cairn mark. The full-bleed master `assets/icon/cairn_icon.png` is
itself one of the generated outputs, not a hand-maintained file.

**Run it whenever `assets/icon/cairn_foreground.png` changes**, then commit the
regenerated files alongside the new artwork:

```bash
python tool/generate_brand_assets.py
```

To check for drift without writing anything (exits non-zero if any derived
asset is out of date):

```bash
python tool/generate_brand_assets.py --check
```

Requires Pillow (`pip install Pillow`).

### What it regenerates

| Output | Notes |
|---|---|
| `assets/icon/cairn_icon.png` | **the master icon** — glyph on cream, full bleed. Every square platform icon (iOS, macOS, Windows, web) is generated from this file by `flutter_launcher_icons`, so it lives here rather than being hand-maintained |
| `assets/icon/cairn_adaptive_foreground.png` | Android-only, vertically recentred — see below |
| `assets/icon/cairn_adaptive_monochrome.png` | Android-only, vertically recentred — see below |
| `brand/play-store/play-icon-512.png` | straight resize of the master icon |
| `brand/play-store/feature-graphic-1024x500.png` | artwork centred on cream |
| `brand/play-store/banner-1280x640.png` | artwork centred on cream |
| `brand/themes/cairn-{dark,amoled,deep}-1024.png` | per-theme backgrounds |
| `brand/light/cairn-light-1024.png` | cream background |
| `brand/transparent/cairn-mark-1024.png` | transparent glyph layer |
| `brand/desktop/cairn.icns` | multi-resolution, 128–1024, cream ground |
| `brand/desktop/cairn.ico` | multi-resolution, 16–256, cream ground |
| `brand/web/favicon.ico` | multi-size 16/32/48, cream ground |
| `brand/web/maskable-512.png` | PWA maskable source, cream ground |
| `web/favicon.ico` | production favicon, copied from the brand source |

Edit none of these by hand — including the master icon. They were hand-built
once and silently drifted a full design generation behind the artwork, which no
filename or config check catches.

### The Android adaptive layers

`assets/icon/cairn_adaptive_foreground.png` and
`assets/icon/cairn_adaptive_monochrome.png` exist only for the Android adaptive
icon, and are separate files from the `cairn_foreground.png` /
`cairn_monochrome.png` pair that every other platform and brand asset uses.

The approved composition deliberately sits ~76px above canvas centre in the
1024×1024 square. That is right for a full-bleed square tile, but Android masks
the adaptive icon to whatever shape the launcher uses and only guarantees a
centred circle of ~61.1% of the canvas survives, so on-device the mark reads as
sitting too high with dead space beneath it. The adaptive pair is the same
artwork translated straight down onto the canvas centre — nothing is resized,
resampled or cropped — and the script fails the run if any visible pixel would
still fall outside that safe circle.

The shift is measured from each layer's own opaque bounding box rather than
hardcoded, so it stays correct if the mark is redrawn. The two layers get
independent offsets (currently +76px and +74px) because the monochrome layer
carries different padding — it has no glow above the top stone.

These are regenerated by the same `build()` call as everything else, so
`--check` covers them; the script just prints their measured geometry first.
`pubspec.yaml`'s `adaptive_icon_foreground` / `adaptive_icon_monochrome` point
at this pair.

### What it does *not* touch

The platform launcher icons under `android/`, `ios/`, `macos/`, `windows/` and
`web/icons/` come from a different generator — `flutter_launcher_icons`,
configured in `pubspec.yaml`:

```bash
dart run flutter_launcher_icons
```

Note that that tool rewrites `ASSETCATALOG_COMPILER_GENERATE_SWIFT_ASSET_SYMBOL_EXTENSIONS`
from `YES` to `AppIcon` in `ios/Runner.xcodeproj/project.pbxproj` on every run;
revert that before committing. The notification icon `ic_stat_cairn.png` is a
separate hand-built asset and is not derived from the app icon.

### Known limitation

The artwork's glowing cream orb measures 1.00:1 against the cream background —
effectively invisible, with its rim only reaching 1.18:1. This applies to every
cream (`LIGHT`) output, which is now everything except the three dark theme
swatches: the master `assets/icon/cairn_icon.png` and all the platform launcher
icons derived from it, both Play Store banners, `play-icon-512.png`, the web
favicon and maskable source, and the desktop `.ico`/`.icns`.

It is the accepted cost of the cream ground, which exists because the stones
themselves were invisible on the old brand purple: the darkest stone pixel
(`#330F5D`) measured 1.09:1 against the darkest part of the master's purple
vignette and 1.34:1 against the flat `#590D86` used for the adaptive icon —
against a 3:1 WCAG minimum for graphical objects. On cream the same pixel
reaches 14.00:1.

This is inherent to using the approved artwork unmodified on a light ground.
The script deliberately does not special-case it; if it needs fixing, fix it in
the source artwork so every variant stays consistent.
